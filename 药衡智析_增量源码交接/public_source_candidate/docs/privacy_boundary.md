# 资料发布与运行状态边界

仓库为 public，`public_source_candidate`、`team_internal` 等目录名不构成权限隔离。用户最新明确授权“保留原有赛题数据并提交所有内容”至同一协作 GitHub 仓库，覆盖此前本轮不发布赛题原件、知识和派生完整报告的限制。本次授权不改变密钥、环境配置和运行状态的排除边界，也不自动授权未来真实企业资料公开。

## 当前允许发布的范围

- 本轮赛题原件及既有数据/知识副本：应用根 `00_赛题原始资料/`、`01_数据/`、`02_知识库/`。恢复按原件源字节复制，不改原题，不用模拟材料替代；本轮恢复校验与清单用于确认字节一致。
- 比赛专属企业配置：`competition_configuration/pharmaceutical_masterdata.json`、`pharmaceutical_terminology_original.json`、`scenarios.json`。它们与 `05_原型/industry_packs/` 中的独立合成企业/数据分离。
- 经整理的静态交付：选定的最新 Word/PDF、逐页图、验收回执、PPT 和演示视频。静态产物来源及实际状态以交付索引和当前运行 manifest 为准，不能把文件存在、模型参与或模拟送达当作真人验收通过。
- 源码、文档、锁文件及独立合成行业参考包。机械/化工仍是迁移参考，并非完成所有细分行业适配；合成数据不是改名后的赛题数据。

密钥、`.env`、数据库、待发队列、完整恢复备份仍不得提交。运行目录不整体搬回或打包；如从中提取已授权的静态回执，须另查凭据、请求头及个人信息，不能夹带持久化调度状态。恢复待发队列可能造成重复发送，因此不随静态交付恢复或重启。

## 复现与恢复

应用根 README 提供显式导出绝对路径的比赛启用命令。`PHARMA_DATA_PACKAGE` 指向已恢复原题目录，`PHARMA_PRIVATE_MASTERDATA_FILE` 与 `PHARMA_PRIVATE_TERMINOLOGY_FILE` 指向比赛配置。两个变量沿用旧接口名称，其中 `PRIVATE` 不是本次授权范围的判断依据。本机外部凭据、原有 `.env` 继续只在本机使用；新机器自行配置所需服务，不能复制开发者密钥。

保留原件及明确配置即可复现资料输入，不把旧源码、旧 `dist` 或整份旧运行目录覆盖到新版本。首次模型调用、PDF转换、模拟RPA及人工审核在新机器分别验证；旧报告和回执不冒充新运行。
