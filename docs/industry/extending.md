# 行业扩展指南 · 哪些可配置、哪些需要编程

本系统定位是**可配置、可扩展的制造业成本智能分析框架**，正式示范收敛到赛题制药场景。本指南说明接入一个新制造企业/行业时，各层工作的边界与做法。

## 三层架构

| 层次 | 内容 | 修改方式 |
| --- | --- | --- |
| 通用技术能力 | 导入、版本、查询、基础成本分析（环比/同比/预算差异/贡献度）、混合检索、模型连接、报告、任务状态 | **维护核心代码**（`05_原型/backend/pharma/`），所有行业共用 |
| 企业配置 | 字段映射、产品、单位、成本要素、预算口径、知识资料、报告模板 | **尽量通过页面配置**（数据中心向导 + 系统设置），无需改代码 |
| 专业策略 | 特殊成本分配、工序核算、在制品/联副产品计价等 | **明确接口、专门实现和验证**（行业包 strategies 注册，不可由上传 JSON 注入） |

## 场景 A：同行业新企业（推荐路径，无需编程）

1. 准备成本宽表 CSV/XLSX：工厂、产品、核算期间、独立产量（完工数量）、成本要素列（材料/人工/制造费用，可自定义要素名）。
2. 页面「数据中心」→ 上传 → 确认建议映射（如「核算期间→期间」「完工数量→产量」，映射方案可命名复用）→ 质量检查 → 查看能力预览（缺什么数据就明确降级什么分析）→ 填企业名称发布。
3. 发布通过完整合同校验（单位/币种/产品版本/口径/聚合一致性）；左上角企业选择器切换即分析。**失败不破坏现有数据**；历史报告仍绑定生成时版本。
4. 知识资料（PDF/DOCX/TXT）在数据中心上传解析，声明适用产品/工厂/期间；「知识中心」重建索引。解析失败会显式失败，扫描件需先 OCR。

限制：该路径分析的是**已归集成本数据**，不等于完整成本核算系统；缺采购量价/用量明细时不会生成严格量价分解。

## 场景 B：新行业（需要少量工程工作）

1. 新建行业包 `industry_packs/<industry>/`：`manifest.json`（要素定义、能力声明、策略注册）、`enterprise.json`（默认企业）、`facts.json`（NormalizedDataset 合同数据）、`knowledge.json`、`template.json`（六章节模板合同）。
2. 若需专业指标（如单位机时、单位能耗），在 `industry.py` 的 `STRATEGIES` 注册受信计算函数——上传的 JSON 不能注册代码。
3. 参考实现：`mechanical_demo`、`chemical_demo`（合成数据，默认不进正式目录，测试可见：`PHARMA_SHOW_TEST_CONTEXTS=1`）。
4. 检索策略按包配置 `retrieval.json`（有界 JSON 策略，需通过合同校验）。

## 场景 C：模型服务接入（无需编程）

页面「系统设置」配置报告生成/决策说明/向量三类连接：服务地址（OpenAI 兼容）、模型名称、协议、密钥。API 与后台任务读同一份配置（`RUNTIME/model_settings.json`，环境变量优先）；连接测试执行一次真实短生成（含身份回显与 JSON 结构检查）。密钥写入本机受限文件，不回显、不入库、不进导出。容器内连接宿主机服务用 `host.docker.internal`（localhost 指容器自身）。

更换生成模型无需重建索引；更换向量模型需重建知识索引并验证后切换。模型不可用时确定性分析与基础报告保留，页面明确标注降级原因。

## 明确不做的事

- 不宣称未实现的完整成本核算（ERP 总账分摊、BOM 展开等属专业策略层，需专门实现与验证）。
- 上传内容永不注册为代码或提词注入；行业包是受信部署物。
- 合成演示数据不进入正式演示目录与评审报告；测试数据保留在测试目录。
