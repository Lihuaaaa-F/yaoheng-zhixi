# 检索、结构化解释与证据合同

当前实现与验收入口见current_run.json。历史GLM v3四场景模型参与PASS、整体PENDING、五个视觉NEEDS_FIX保留于外部历史归档；不是本轮重跑。

PDF按页、DOCX按段落/表格、TXT按行段解析。行业包可补JSON合成知识。FTS5 BM25与CPU ONNX向量均先在企业/行业/产品/工厂/期间/规格适用范围内筛选；101条反例用于回归。LlamaIndex BaseRetriever/TextNode真实执行融合结果，不只是依赖声明。索引候选构建校验后原子CURRENT切换；失败保留原索引。

context_services.retrieve按不可变AnalysisContext选择知识目录与独立索引；同文档ID不能跨企业混用。源快照、嵌入、检索器、融合参数进入版本与生成缓存。检索执行成功、零召回及结论证据不足分别表达。术语与制药规则在pharmaceutical包，公共核心不写药名分支。

numeric_fact须绑定指标；document_fact须绑定来源位置及引用；hypothesis须保持待验证语义并具备适用证据与缺项；insufficient_evidence须有非空正文、具体缺项和逐句缺证语义。全部超过±10%的要素/口径alert_id与主要差异必须有合格模型解释或具体缺证段落，summary-only不通过。允许最多2次修复且持久调用预算，切筛选复用同输入缓存。行动字段统一类型化渲染，拒绝残留[[...]]和{{...}}。

协作默认glm-5.3-flash；本机用户授权DeepSeek覆盖独立配置。响应model身份核验、逐调用usage累计，模型故障退规则但不冒称模型成功。词义规则是保守校验而非因果证明，真人归因评分仍必须真实评审。详见retrieval_contracts.md。

最终实证追加：原S3的适用维修事件确实在隔离后的候选中，宽泛查询曾将它排在前八之外，不能写成原题缺维修资料。制药包采用有预算的分目的补查与去重，补入当前产品和期间适用的事件证据，总量上限不变；配置版本参与缓存失效。该改进用已知场景作回归，不是未见问题的质量证明。事件仍只是待验证机制证据，不是已证实净原因。
