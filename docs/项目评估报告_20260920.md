## 二、主要问题与风险评估（评估基线 2f5264e 时点）

### 已于本日修复（提交 2399d38，定向回归全绿）

1. **单位口径**：通用报告选"总成本"时对标表仍标"元/件"，且验收器用同一错误单位导致漏检 → 数值/单位/标题/差异公式现共用同一口径来源（`benchmark_unit_of`），篡改单位的负例测试会 FAIL。
2. **检索范围**：非赛题知识检索丢弃用户选择的工厂与检索模式 → 范围（企业/工厂/产品/期间/模式）现贯穿请求→检索→结果，并回显 `requested_scope`。
3. **验收合同**：业务验收硬编码"绑定数≥70 或 generic-v1"→ 改为版本明确的合同（generic-v2 自带 `expected_bindings` 下限；未知合同 fail-closed）。
4. **模型路由**：`generate()`/缓存指纹/worker 版本核对各自构造网关，路由配置可能与实际调用不一致 → 三处统一经 `for_route('narrative')`。
5. **降级重试**：DEGRADED 报告被缓存返回，服务恢复后无法重试 → `retry:true` 明确重试，旧结果保留、新任务复用确定性计算。
6. **Agent 决策**：只看任务状态不看产物健康 → 现同时检查存在性与可用性（哈希），损坏产物触发 REPORT_NEEDED。
7. **任务列表**：先全局截断 100 再按企业过滤（历史任务可能消失）→ SQL 内先按业务范围查询再分页（limit/offset）。
8. **启动状态**：worker 退出仍提示启动成功 → 启动成功现要求 Web 就绪 + worker 心跳新鲜，失败给出可操作中文提示。
9. **配置自包含**：正式制药口径依赖外部绝对路径环境变量（主数据/术语），裸仓库启动即 306 项校验失败 → 默认解析仓库内 `competition_configuration/`，部署不再依赖 worktree。
10. **跨路径口径**：通用/制药两套聚合公式存在重复维护风险 → 落地共用指标合同（`metric_contract.py`）+ 三上下文跨路径回归锁。

### 本日仍在收敛的差距（对应五阶段计划）

- **产品完整性**：数据接入仍是"预设导入任务"（`POST /api/imports` 无载荷），缺少上传→预览→映射→质检→发布向导；知识中心缺文档上传/解析状态；模型设置无页面化配置与连接测试。→ 本日起实施（阶段 2/3）。
- **交付便利性**：Docker 三服务 + 桌面启动器本日落成并实测（阶段 4）。
- **评审证据**：三场景人工 0–5 评分（真人）、含完整对标顺序的演示视频补录、报告/录像/PPT 与同一交付状态的对应声明（阶段 5）。

### 风险定性

- **架构**：模块化单体 + SQLite WAL + 单 worker，规模适配赛题；并发写侧已有 `BEGIN IMMEDIATE` 与文件锁，风险可控。
- **安全**：密钥仅经 `PHARMA_MODEL_KEY_FILE` 文件注入，.gitignore 拦截 `.env/*.key`；模型异常文本脱敏；RPA 仅回环（本日为 Docker 增加显式 opt-in 的内部模拟器白名单，默认行为不变）。
- **诚实性**：系统在"缺数据不乱算"上做得突出（缺明细拒绝量价分解、合成数据全程标注、模型参与单独验收维度），这是评审可信度的核心资产，后续工作不得绕过。

4. 短板明确且可收敛：真人评分与补录视频属"必做动作"；数据接入/模型设置页/一键部署属本日工程范围。**若阶段 2–5 未完成（尤其真人评分缺失、视频缺完整对标顺序），存在被按"交付不完整"降档的实际风险。**
