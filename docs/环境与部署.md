# 环境、部署与复用

| 组件 | 版本/位置 | 接入方式 |

这些是本机实测位置，不要求其他机器使用相同用户名、目录或盘符。根目录可选的 `环境接入.local.sh` 仅保存本机接入变量，已排除在Git之外；`安装.sh`、`启动.sh`、`停止.sh` 会读取它。密钥放在项目私密配置或系统设置保存目录，不写入共享可读目录。

## 其他项目如何复用

Python依赖相容时复用上述独立虚拟环境；不相容时在 `/opt/dev-envs` 下按版本建立另一独立环境。先通过虚拟环境的Python执行 `-m pip install -r 05_原型/requirements.lock`，再设置 `PHARMA_PYTHON`，不使用 `sudo pip`，不更换Ubuntu系统Python。共享目录由管理员创建并授予所需普通用户或开发组写权限，不使用 `chmod 777`。

Node工具链和包缓存可共享，但 `node_modules` 只允许兼容锁文件复用。新锁文件建立独立依赖目录，运行 `npm ci` 后再连接到对应项目；不要把项目依赖全部全局安装，也不要让一个项目的 `npm ci` 改写其他项目的依赖集合。

向量模型可只读共享，项目通过配置指定模型目录；模型安装和下载检查使用 `05_原型/scripts/fetch_embedding.py` 及 `docs/embedding_manifest.json`。不配置全局 `PYTHONPATH`，测试或启动命令仅在自己的进程环境内设置源码路径。

## 首次部署

1. 安装兼容Python、Node/npm、Git、LibreOffice、Poppler和中文字体。
2. 克隆源码，按锁文件安装依赖，执行根目录 `安装.sh`。
3. 如需模型分析，在“模型连接”分别配置授权的分析、提取、助手连接；安装或指定真实ONNX向量模型及分词器，再构建知识库。
4. 执行 `启动.sh`，访问 `http://127.0.0.1:8765`。停止时使用 `停止.sh`，保留数据目录。

普通用户运行全部服务。需要管理员安装时在本地终端输入sudo密码。模型调用预算沿用明确配置，不因测试失败自动扩大或更换套餐。

## Docker和Windows入口

已有Docker Desktop WSL集成或Docker Engine时直接复用。使用 `05_原型/deploy/docker-compose.yml`，镜像内安装Python依赖、前端构建产物、LibreOffice和中文字体，原题资料只读挂载，运行数据和产物使用命名卷。容器不依赖本机 `/opt`。

`药衡智析启动器.bat` 调用 `05_原型/deploy/launcher.ps1`，支持启动、更新构建、停止、状态和打开页面。Windows可访问WSL中的项目目录；启动器优先Windows Docker CLI，按实际可用发行版回退到WSL Docker。

网络限制时可显式使用镜像源构建，例如：

```bash
docker compose -f 05_原型/deploy/docker-compose.yml build \
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
docker compose -f 05_原型/deploy/docker-compose.yml up -d
```

本机原生与Docker默认占用同一Web端口，启动另一模式前先正常停止当前模式。不要清理其他项目的容器、镜像或数据卷。

## 数据与恢复

原生运行数据库默认在 `05_原型/.runtime`，产物默认在 `07_交付/业务报告`；本机私密配置可以指定独立子目录。备份应包括运行目录、产物、上传原件与本机私密配置，备份文件不进入Git。数据库备份时正常停服或使用SQLite备份接口。

报告与历史评分按文件内容及任务版本关联。项目迁移后必须复核下载与来源路径；模型或生成失败会如实标记降级，不能用“文件已生成”代替内容质量通过。
