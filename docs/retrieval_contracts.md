# 检索与解释合同（本轮工程实现）

维护范围：`knowledge.py`、`narrative.py`、`context_services.py`、制药包 `terminology.json`、`narrative_rules.py` 及固定可信注册入口 `industry_rules.py`。协作默认应用模型为 `glm-5.3-flash`；本机本轮经用户授权，通过独立环境配置覆盖为 DeepSeek 官方兼容接口的 `deepseek-flash`，未更改协作默认值。实际调用身份、运行结果和本机覆盖状态以唯一当前运行 manifest 为准；开发 Agent 不代表应用模型。真人署名、0–5归因评分及视觉审核不由本模块代填。制药原合同的工艺假设、专属岗位建议和跨厂资料要求位于制药包代码策略，公共核心保留数值绑定、验证器与通用核查动作。固定代码入口只加载随源代码审查的文件，不从上传配置读取可执行路径；修改代码策略后受控重启。

## 适用范围与快照

`context_services.retrieve(snapshot, query)` 是API和worker共享入口。竞赛企业读取PHARMA_DATA_PACKAGE指定的原题资料（可用本仓授权保留原件或工程外副本），合成企业仅读取其行业包 `knowledge.json`。完整不可变 `analysis_context` 决定索引目录；每个证据单元均绑定企业、数据集、行业及版本、知识快照。引用时再次核对范围，缺少绑定也不能当跨企业通用证据。

`knowledge_snapshot` 是原始知识源指纹，`knowledge_version` 是包含解析器、嵌入版本和上下文的索引版本，二者不能直接比较。读取前校验源与绑定指纹一致。索引解析失败不会替换 `CURRENT`；向量不可用明确降级，可保留词法召回。`status` 表示检索执行质量；`recall_status` 分别表达有召回、无匹配、无适用候选，不能把检索成功直接说成证据充分。

BM25在SQLite适用候选表约束后排序并取限额；Chroma通过已入库的 `evidence_id` 元数据筛选候选再查询。不存在先全库top100再过滤的截断。RRF与实际执行的LlamaIndex `BaseRetriever/TextNode` 保留。重排序器不得引入原候选以外ID。

## 模型解释与缺证

每个 finding 须有非空正文。数字事实必须绑定指标，由程序重建数字句；文档事实必须匹配定位摘录（仅允许下文列明的归一化与有序省略）；假设须同时有指标、适用证据、摘录、具体待补资料和不确定语义；整改建议须完整核查字段。

`insufficient_evidence` 必须逐句表达缺证或待核查，且提供具体记录/测量项。缺证正文最终由程序编译为明确的不足与待核查句式，不能通过类型标签或尾部免责声明携带确定因果。该有限合同有意保守，可能要求合法但复杂的模型句子改写；它不是通用自然语言因果证明器。

必要解释包括主要单位差异要素与全部触发告警。模型 `alert_refs` 对应确定性 `alert_id`，并按要素与单位/总额口径展示。只统计已通过完整合同的假设/缺证解释；摘要数字复述和孤立文档事实不能充当原因解释。缺项复用已有最大两次修复预算和持久化调用上限，完成结果可缓存，不因界面筛选自动无限调用。

所有可见文本字段使用同一类型化渲染，包括建议、核查对象、预期证据、责任岗位、部门、截止依据。未知 `[[...]]` 或 `{{...}}` 均拒绝；合法上下文、指标及引文插槽在进入报告和任务前解析。

生成缓存包含实际snapshot、证据、上下文、模板、prompt、验证器、模型/供应商/端点、生成参数以及检索模式、版本、嵌入版本和融合权重。缺身份或身份不匹配不算目标模型成功；usage继续跨修复累计。

## 本轮证据与边界

`tests/test_evidence_contracts.py` 仅含独立合成数据。修复前实际重现五种缺证标签绕过与适用证据位于第101位漏召回；修复后加入全告警覆盖、辅助字段插槽、同ID跨范围拒绝、缓存失效、向量候选约束、索引失败保留旧快照、并发A/B/A，以及三个公开包经检索到假网关解释的测试。假HTTP模型返回身份属于协议测试，不能视作真实GLM调用。

本机三公开上下文的真实本地BM25、CPU向量和LlamaIndex混合检索已执行并召回其各自证据。这些问题是明确的回归集，未作检索泛化质量或行业专业归因质量结论。真实模型实调、端到端导出/RPA和人工审核以唯一当前运行manifest为准。

GLM-5.3后续先选择一个行业深入补齐资料许可、产品适用范围、真实字段与专业限制。在包内维护知识、术语和证据门槛，并以独立未见问题评测召回；新增策略先给最小反例。不得将参考包规程说成真实企业制度，也不得复制整个后台。Flash只按需视觉检查，不能代真人评分。


## 历史合同演进（以下版本记录不代表当前版本）

## 本轮实调后的语义角色修复

真实浏览器发现模型使用合法指标ID，将单位成本写成总额，并将同一本期指标同时描述为基期。该输出已作为失败证据保留。v13编译器从 `alert_id` 对应的确定性 `current/base/value_unit/rate` 生成全部告警数值前缀，正文不接受自由告警数值槽，仅可保留语义明确的本期单位成本说明。普通解释也检查基期/本期角色、总额/单位/比例量纲；合法指标ID本身不证明句子语义正确。Prompt及validator版本同时更新使旧缓存失效。公开合成负例先实测失败后修复通过；真实DeepSeek修复轮存在被拒的无效条目时保留mixed/DEGRADED，不以告警覆盖为由清除失败状态。


## Task式输出与相对期间词法

v14输入端为每个必需章节建立 `task_id`，绑定不可变指标与该章节全部告警。模型只返回定性解释、引用、具体缺项和可选整改建议；编译器按已存在的task_id绑定section、metric_refs与alert_refs，既不生成假设正文，也不推测缺失的任务。未知/重复task和上传绑定覆盖均拒绝；原findings接口保留严格兼容校验。假设保留指标引用不要求正文重复数字，告警数字仍由确定性编译器负责。总行数上限根据任务数计算并设硬上限，合法新增要素不再撞固定八条限制。

实调定位了真正词法误拒：“下一月度成本分析前”的“一月”被误认成自由数值。现在月度/年度相对结账周期与数值单位区分；无绑定金额、阿拉伯数字与中文“百分之十”等仍拒。该错误有先红后绿的正反例。已有三份真实DeepSeek任务式响应修复后离线重验通过；记录明确标为OFFLINE_REVALIDATION，不追认原失败运行、不冒充重新实调。独立实调保持每轮至多三次，不扩大修复预算。


## v15：单元修复、绑定期间与期限提议

修复状态以 `(task_id, explanation/recommendation)` 为单位。通过完整合同且告警覆盖完整的解释及通过完整行动合同的建议分别冻结，后续重复输出不能覆盖或污染它们。失败单元仅能由同单元的新合法输出解除；省略字段、返回null或重复另一合法单元都不能清除错误。公开合成回归实证并修复了旧实现“省略失败行动即可清错”的绕过。状态记录在 `unit_validation`，历史失败仍留在 `failure_reasons`。

期间来自不可变snapshot的实际期间及指标声明的comparison_period。仅这些已注册的年月/日期允许中文日期规范化和引用；未知月份或未注册的具体日仍拒绝。日期归一不会改原文引文。

行动期限允许有界的类型化建议：固定月度结账、月度分析完成、月度复核完成或报告完成锚点，加一至三十个工作日。只在deadline_basis字段内编译为 `DeadlineProposal(anchor, working_days, requires_confirmation=True)`，并记录数字绑定；不自动生成确认截止日期，不推断节假日。期限以外的金额、比例及无依据日期仍须原有绑定。原来的缺证逐分句与因果伪装反例保持严格，无宽泛放行“可能”。

上述缺陷对应的旧正式运行失败状态保持。利用原真实响应的本地离线序列重放可验证新编译器和状态机，记录必须明确 `OFFLINE_REVALIDATION_AUTHENTIC_RESPONSE_SEQUENCE`、`new_network_calls=0`；不将离线重验算作新的模型实调通过。


## v16：独立跨厂解释任务

存在可比 `benchmark_context` 时，`explain:benchmark` 是独立必需任务，不能用主驱动或月环比告警章节代替。任务只绑定该比较声明且已存在于snapshot的 `benchmark:` 指标；绑定方向、左右工厂、期间与限制。月度指标即使数值合法也不能被放进跨厂任务。没有类型化跨厂指标时仅允许明确缺证，不借用单厂数字；显式不可比上下文不宣称可归因。

跨厂缺证解释和可执行建议分别通过原有单元合同，正文同时显示由程序绑定的方向和限制。只有一厂证据时，不据此证明另一厂原因；缺少对方明细必须明示，不能编造下钻。公开合成测试覆盖“其他章节通过但跨厂任务缺失仍失败”、合法跨厂缺证和建议、月环比指标混入拒绝、缺跨厂指标不回退以及显式不可比情况。

本轮不迁移旧Prompt缓存。新版本完整重新生成，旧cache不能因为原章节通过就被认作新的跨厂解释通过。未来若做局部补充，必须逐单元重新验证输入与证据版本、当前合同及原调用身份，标明继承来源，并仅为尚缺的新任务调用模型；不能继承旧整体PASS或旧审核。该优化本轮未实现。

2026-09-18 合同词法修复（validator `claim-contract-v8-specific-cost-documents`，Prompt 仍为 v16）：具体成本核算表、成本对比表、成本计算单与费用分摊口径说明属于可核查证据制品。新增的识别规则同时要求业务对象与文档类型，不接受泛称“相关对比表”“成本情况说明”，也不允许把确定因果断言伪装成缺证清单。没有放宽缺证正文逐分句限制。新增五个合法制品红例与六个模糊/因果负例，相关七个测试文件合计 101 项通过。对已存两场景模型响应作离线 MockTransport 回放，结果均通过；这不是新模型实调，不改写原失败运行或旧缓存。原始响应及回放记录仅存本地运行目录，不随公开源码交付。

## 当前执行合同与审计修复

当前 Prompt 为 `ranked-diagnostic-paths-v6-bounded-batches`，验证器为 `useful-bounded-attribution-v9-unit-suffix`；上述 v13—v16 与 claim-contract-v8/v9 是历史记录。生成缓存绑定当前版本，不能继承旧缓存的通过状态。当前解释要求两至三条有优先级、可反证的诊断路径，包含机制、依据、核查、所需资料及预期结果；价格与耗用联合判断必须具备两期或两厂的采购价、实耗及合格产出资料。

C1—C5 的有限放宽边界如下：

- C1：整数或一位小数简写，仅在注册指标按 ROUND_HALF_UP 同精度舍入后唯一匹配、单位/期间/指标对象一致时绑定；歧义与编造数字继续拒绝，绑定写入 numeric_bindings。总额指标不得追加“元/盒”或分母伪装为单位成本。
- C2：引文只归一化空白、引号和破折号；省略号连接的每段须至少四字，并按原文顺序命中。不得用改写、重排或短尾片段引入新事实。
- C3：未进入当前召回列表的引用可按 ID 查询当前上下文的知识库，但必须真实存在、适用且通过摘录验证，写入 evidence_rescued；显式排除的证据、跨企业或错误文档版本不能救回。
- C4：缺证约束按句（句号、分号、问号、叹号及换行）检查；同句逗号从句不逐项重复限定词。确定因果仍拒绝，后置免责声明不能抵消前面的肯定因果。
- C5：响应身份仅接受精确模型名或受控配置的已核实别名。`PHARMA_MODEL_VERIFIED_ALIASES` 供运维登记已有探测证据的映射，不是运行时自动核实；缺失或不匹配身份不算模型通过。

知识索引 parser 为 `scope-prefilter-v10-source-fingerprint-identity`。不同目录的同名文件独立计入指纹及引用源哈希，源目录中的 knowledge.json 参与快照。术语缓存按文件路径、大小及修改/创建状态失效；分词不重复读盘解析同一份术语。manifest 和 chunks.json 以 UTF-8 临时文件原子替换，损坏 manifest 可重建。

自动检索与报告预构建对相同失败输入指纹复用失败记录，源文件、术语或模型变化会重新尝试；用户显式构建可重试。解析失败时 CURRENT 不变，若有旧有效索引则提供明确 DEGRADED 的旧版本词法证据及失败原因，不冒充新知识版本成功。向量链路不使用与当前配置不一致的旧向量。

向量切换的真实样本必须维度一致且全部有限；模型适配结论须符合当前运行器的 CLS 池化、L2 归一化与固定查询前缀，其他策略明确拒绝。所有切换异常均恢复旧配置和切换前 CURRENT；不依赖重新解析可能损坏的源文件完成回滚。知识图谱剂量单位来自行内声明或表头，缺失时保留未知，不默认补 kg。

针对性验证使用独立合成知识、临时数据库和假 HTTP 网关，覆盖旧索引服务、失败重试、指纹、manifest、文档版本、单位、向量非有限值、回滚、UTF-8 审计、三种 recall_status、重排序越界与修复预算边界。它不替代真实模型调用或视觉验收。
