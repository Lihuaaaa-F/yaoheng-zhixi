## 三、P0 问题详解（演示/交付前必须解决）

### #1 模型违约致报告+对标全线 DEGRADED（主线性命门）

**证据（本次实测）**：
- 强制重生成报告（job `eddf813da89c461b947550524bcfa4d7`，`retry:true`）：`narrative.status=DEGRADED`，failure_reasons 共 6 条——`free business number forbidden` ×5、`missing evidence must name specific records` ×1；与昨晚及此前全部失败同根因。
- 对标冷请求（银黄口服液 2026-06，产品×月份未命中缓存）：60.6s 返回且 DEGRADED，`insufficient evidence text must state an evidence limitation in every clause` 等。
- 验收明细：`model_participation=FAIL`、`evidence_applicability=FAIL` → 整体验收 FAIL。
- 新生成 PDF 首页永久横幅："本次采用基础分析，原因解释待复核"。
- 运行库最近 8 个任务：5 DEGRADED + 1 本次 DEGRADED + 2 FAILED，无一 PASS。

**影响**：评委现场点"生成报告"或"跨厂对标"即露馅；"归因自动生成"是赛题 5.2.3 与全部加分叙事的卖点，当前出厂默认配置下不可复现。

**修复方案（按优先序）**：
1. **切换默认路由到已验证链路**：历史回执记载 DeepSeek 备选七次实调通过——将 `PHARMA_MODEL_ROUTES` 的 narrative 路由默认指向 DeepSeek，glm-5.3-flash 降为备选端点；切换后现场重生成三场景验证非 DEGRADED。
2. 若必须用 flash：改合同实现方式——数字槽位从"要求模型输出 `[[metric:id]]` 语法"改为**后处理数字提取替换**（模型自由行文，程序把数字替换为注册槽位值；无法绑定的数字整段拒收），并在 prompt 中加 2-3 个 few-shot 合规示例。当前失败全部是"自由数字"，说明 flash 稳定理解不了槽位语法，靠重试无法收敛。
3. 兜底：演示用预生成报告 + 开场诚实声明降级边界（但这等于放弃归因卖点，仅作保底）。

### #2 降级结果粘住：前端无重试出口

**证据**：后端降级缓存机制要求 `retry:true` 才真重试（2026-09-20 修复引入）；但前端 `Tasks.tsx:22` 与 `NarrativePanel.tsx:11` 调 `POST /api/reports` **均不传 retry**。本次实测：默认 POST 直接秒回昨晚的 DEGRADED 缓存（`cache_source_time=2026-09-20T18:19`）。

**影响**：服务恢复后用户在界面上**永远拿回降级结果**，无任何出路；"降级重试"修复对用户不可见，等于没修。

**修复方案**：结果为 DEGRADED/FAILED 时，"生成报告"按钮变为"重新生成（忽略缓存）"并传 `retry:true`。十分钟级修复，直接打通用户唯一痛点路径。

### #3 Compose 构建默认代理，净评测机必败

**证据**：`05_原型/deploy/docker-compose.yml:17-18` build args 默认 `http://host.docker.internal:7897`（本机 Clash）。

**影响**：干净评测机无此代理时 pip/npm 构建直接失败——"一键启动"承诺在评审环境当场翻车。

**修复方案**：默认值改空串（本机有代理时显式传 `PHARMA_BUILD_PROXY`）；交付前在无代理环境做一次净机演练。一行级修复，不做就是交付事故。

## 四、P1 问题详解（显著影响演示与可用性）

### #4 安全硬伤：任意文件读取+外发、无鉴权

**证据**：`GET /api/settings/models/list|test` 接受任意 `base_url`/`key_file` 参数（api.py:452-460），`model_settings.py:168-169` 直接 `Path(key_file).read_text()` 作 Bearer 发往任意 URL；全部端点无认证、无 CORS 中间件；`deploy/entrypoint.sh:9` 绑 `0.0.0.0`（compose 端口映射限 127.0.0.1 兜底）。

**影响**：任意本机进程可借该端点读任意文件并发往外部；`PUT /api/settings/models` 可被任意可达者写入密钥配置。

**修复方案**：`key_file` 限制在 `runtime/keys/` 白名单内；`base_url` 要求 https 或显式 opt-in http；演示形态加最小 token（一次性 header 即可）；entrypoint 与 compose 口径统一为 127.0.0.1。

### #5 对标 60s 同步阻塞 + 全局模型串行锁

**证据**：`/api/benchmarks` 在请求线程内调 `generate()`（api.py:145）；`complete()` 全程持 `model-call.lock` 跨进程文件锁（narrative.py:688），单次 55s 超时×3 重试+sleep 20/40（narrative.py:749），极端持锁~4 分钟，期间**所有**模型调用无限期阻塞。

**影响**：演示中两个模型功能不能并发使用；页面同步等 60s+。

**修复方案**：对标改异步 job + 前端轮询（复用现有报告队列基建）；锁粒度从全局一把改为按任务一把。中期项；演示前至少加进度反馈与预期管理文案。

### #6 热力图每次请求 14s（比已知更严重）

**证据（本次实测）**：首响 14.5s、**第二次 14.5s、换月份 13.1s**——不是首响问题，是每次都慢。根因：`dashboard.py:77-98 product_month_grid` 对 3 产品×6 月=18 次全量 `analyze_reference`（每次~0.8s 整库加载+Decimal 聚合），无任何缓存。

**影响**：工作台首屏挂载即请求，用户每次进入/切换都盯空白热力图 14s。

**修复方案**：单次数据加载后聚合 18 格（或按 `data_version` 进程内 LRU 缓存快照）。半天级修复，收益覆盖整个首屏体验。

### #7 RAG 三类知识覆盖不全（赛题 5.1.2 字面缺口）

**证据**：知识库实际仅 7 份 PDF 入库；药材行情/行业基准是 **CSV，走数据层未入 RAG 库**；赛题点名的"历史成本异常处理记录""同集团对标基线"两类企业内部知识**完全缺失**（题包未提供，团队也未补建）。验收清单宣称"三类知识全部入库 ✅✅"与事实不符。

**修复方案**：行情/基准 CSV 以表格文档形式切块入库（解析器已支持表格标题继承）；从设备清单维修历史派生"异常处理记录"文档；补建"对标基线"文档。直接补齐赛题字面要求。

### #8 长耗时操作无进度反馈

**证据**：报告~80s 仅按钮禁用（Tasks.tsx:22）；对标~60s 仅静态文案"正在读取固定版本数据…"（App.tsx:21,30）；热力图~14s 无任何提示。正面：NarrativePanel 每 2s 轮询 stage、Tasks 页轮询任务状态。

**修复方案**：统一长耗时模式——进度条/阶段文案/预计耗时/可取消；至少复用 NarrativePanel 的轮询 stage 模式。

### #9 全站零重试 + 三处静默吞错

**证据**：无任何"重试"按钮（api.ts:6 仅文案让用户自己重试）；`Analysis.tsx:26` forecast 失败 `catch(()=>{})` 无提示；`DecisionCard.tsx:19` 决策卡失败整卡消失；`DataCenter.tsx:40` 导入历史失败静默置空。行业目录首载失败后页面近空白且无法恢复。

**修复方案**：统一错误组件（消息 + 重试按钮）；三处吞错补用户可见提示。

### #10 前端类型系统缺失

**证据**：api.ts 仅 2 个类型定义；全项目 55+ 处 any（DataCenter 15、Analysis 13、ModelSettings 9）；手工猜 API 形状 `x.industries ?? x.packs`、`j.jobs ?? []`——后端字段一改前端静默空白。

**修复方案**：按后端 Pydantic 模型一次性生成 TS 类型（脚本生成即可），消灭 any 与猜字段兜底；这是后续一切前端重构的地基。

## 九、专项评估一：全局规划缺失（用户判断成立）

1. **信息架构**：工作台"报告倾倒"（#24）；数据中心/知识中心/设置三页是后补的（03a5a30），与主工作台的信息层级未统一设计。
2. **代码组织**：后端 27 模块/前端 17 文件平铺；核心"版本指纹→缓存键→验收合同"逻辑分布在 worker/api/narrative/reports 四处（#21）——"改一处必须处处同步"的事故温床。
3. **配置无统一入口**（#22）：换机即断的硬编码相对路径。
4. **交付态无锚点**（#16）：三个版本互不对应；README 顶部堆叠历史更新日志而非用户入口；应用藏在五层中文目录深处。
5. **正面**：部署层规划质量高（compose 三服务健康检查/持久卷/密钥文件注入、启动器防重复启动与分级失败提示）——规划缺失集中在**产品层与代码组织层**。

## 十、专项评估二：用户思维缺失（用户判断成立）

以首次使用的成本会计视角走完全流程（DOM 文本走查 + API 行为）：

1. **降级/失败用开发术语甩给用户**："解释合同：待补充或复核"上屏；"请查看开发者详情"指向空壳（#27）；"自动模型解释未开启；当前为确定性分析"——用户无法分辨是功能开关还是故障。
2. **死路无出口**：DEGRADED 无法重试（#2）；forecast 静默失败；决策卡失败消失；行业目录首载失败页面近空白（#9）。
3. **等待无反馈**：80s/60s/14s 三处（#8）。
4. **命名与口径打架**：页签文案分裂（#13）、任务卡口径（#14）、行业参考（#25）。
5. **正面**：口径溯源（点击看分子/分母/来源 CSV）、N/A 带原因、贡献度不裁剪——这套诚实性是用户信任的稀缺资产；问题集中在**降级/失败/等待三类"不好看时刻"完全没有体验设计**。

## 十一、公平清单（站得住的部分，修复时不得破坏）

- 确定性计算独立重算零误差（历史独立审查已验证）；回归 314+1 一比一复现。

- Comose 三服务健康检查/持久卷/密钥注入 + 桌面启动器失败提示质量高。
- 口径溯源链路完整可用；知识库 154 chunks 逐源 SHA256；模型身份核验机制在工作。
