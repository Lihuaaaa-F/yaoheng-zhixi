## 实际架构与数据契约

```text
React + TypeScript + Vite + ECharts
                 │ HTTP / OpenAPI
                 ▼
FastAPI 单体 ─── SQLite WAL：快照、任务、审计、outbox
   │                     │
   ├─ ingestion/metrics  └─ 单 worker：报告阶段与RPA发送
   │    DuckDB读取版本Parquet；Decimal计算
   ├─ knowledge：jieba FTS5 + Chroma/ONNX + RRF + LlamaIndex
   ├─ narrative：OpenAI / Anthropic格式 → DeepSeek
   └─ reports：原DOCX工作副本 → python-docx → LibreOffice PDF
```

数据源10CSV、334行；标准快照发布前检查表头、主键、缺失、范围、月份与成本勾稽。失败保留旧current并记录拒绝原因。指标包含metric_id、原值/展示值、单位、公式版本、分子分母、比较期、行键及源哈希。预算仅一厂可用，二厂不造明细。行业单位按规格除10/20/60，静态“本厂水平”不当所选月份实测。

贡献度分单位与总额，负值及超过100%保留；无基期或零总变动返回N/A。单位告警原始数据不触发，总额45个有效环比中31个触发；单位阈值通过隔离变异验证。季度按Σ成本/Σ产量，完整对应季度比较。跨厂默认二厂−一厂，以一厂为分母；交换方向同步交换分母。

API与界面跨厂入口当前按所选**月份**比较；季度报告内部按完整季度生成对标。两种范围不可混称同一个季度结果。所有期间展示应明确，不把跨年邻行当上月。

## 模板与生成

原DOCX是权威，工作副本保持唯一。人工/制造费用同名标签按XML位置区分金额与比例；动态原料、趋势、市场、对标、建议和任务表在锚点插入。81个数值绑定位置检查、六章节、占位残留、表图及重复单位门禁已实现；最终验证仍需源记录和代表页面复核。合计贡献度缺基期/零变动时N/A，不能因表格存在认定口径正确。

Finding同时记录类型、指标/证据引用、原文摘录、缺证项和建议。模型不得计算；数值事实由程序输出，文档事实逐字验证，原因只作为假设。有限超时、最多两次修复、持久调用上限，成本无法核价记UNKNOWN。缓存与worker检查模型、协议、端点、提示、数据、知识和模板版本；发生版本漂移要求重新提交。

报告阶段：VALIDATING→COMPUTING→RETRIEVING→GENERATING→RENDERING_DOCX→CONVERTING_PDF→VERIFYING→SUCCEEDED/DEGRADED/FAILED。Word与PDF独立状态，产物ID限定受控目录，校验哈希后下载；规则降级报告不能称完整大模型验收。

## 原RPA合同

POST `/api/rpa/tasks`包含task_id、task_title、嵌套assignee/source、priority、deadline、created_at、suggestion、notify_method。用户编辑确认后事务写入outbox。HTTP200且body.code=200、ID匹配、status=sent及notify_status正确才为模拟发送成功；不调用第二个微信接口。400/超时先GET同ID比对payload，冲突停止；无法确定记DELIVERY_UNKNOWN。原mock重启清空，曾发送后404记REMOTE_UNKNOWN，不重发。截止日按演示当前日期生成，不照抄旧样例。
