## 1. 模块一：智能成本分析报告生成

### 1.1 报告模板解析（赛题 5.1.1）——✅✅

**要求**：解析 Word 模板，识别固定章节标题与动态占位符（`{{产品名称}}`、`{{本月材料成本}}`、`{{环比变动率}}`）；模板至少 5 章节。

**实现**（`backend/pharma/reports.py: normalize_template / binding_semantics / build_bindings / verify_docx`）：
- 直接解析**题包原模板**（`00_赛题原始资料/…/04_报告模板/*.docx`），不自造模板；正则 `\{\{([^{}]+)\}\}` 提取全部占位符；
- 每个占位符登记一条语义记录：原名、语义字段、所在 XML 部件与段落序号、书签锚点、上下文原文、单位、数值来源（快照字段路径）、缺值策略（"N/A 并说明缺值原因"）；中文占位符名由 `binding_semantics()` 映射到确定性字段（例："材料环比比例"→`elements[materials].unit_mom`，单位 %；含预算/同比/产量/工时/时薪/效率/费用明细全套映射）；
- 工作副本与原件分别记录 SHA256，模板变更可检测。

**原理**：占位符→字段路径的**映射表驱动**设计——新增字段只需加一行映射；渲染期从确定性快照取值，模板文字不参与数值计算；书签锚点让验收器可以按位置核对而不是全文搜索。

**效果**：题包模板占位符 100% 完成语义登记；报告验收器按**角色+章节位置**逐一核对可见数值（含显示精度与单位），附录或别处出现的同数字不能顶替；任何残余 `{{}}`/`[[]]` 占位符即验收 FAIL；负例测试（删除模型解释后验收必须 FAIL）在 `test_report_layout_direction.py` 锁定。

### 1.2 RAG 知识库检索增强（赛题 5.1.2）——✅✅

**要求**：制药专属知识库含产品知识（配方/工艺路线）、行业知识（药材行情/GMP/行业基准）、企业内部知识（设备清单/异常处理记录/对标基线）；格式 PDF/Word/TXT；语义+BM25 混合检索；结果标注来源。

**实现**（`backend/pharma/knowledge.py`）：

*知识覆盖*：题包 `03_制药知识文档` 三类知识全部入库（配方文档、工艺路线文档、GMP 法规摘要、车间设备清单含维修历史、药材市场价格、行业基准）；解析支持 PDF（PyMuPDF，按页）、Word（python-docx，按段落/表格，标题继承）、TXT（按行分块）。

*检索原理*（双路召回 + 融合 + 预过滤）：
1. **分词**：jieba 加载制药术语词表（产品名/别名/设备别名/分词词表），词表哈希绑定进知识版本——换词表必然重建索引；
2. **关键词路**：SQLite FTS5 BM25，查询词 OR 组合；
3. **语义路**：ChromaDB 持久化 + bge-small-zh-v1.5 ONNX 量化 CPU 推理（CLS 池化归一化，查询加"为这个句子生成表示…"指令前缀，512 截断，批 16），无 GPU 依赖；
4. **范围预过滤先于排名**：候选先按产品/工厂/期间/规格/文档版本/生效日期/事件期间过滤，再进 BM25/向量排名——不相关的证据根本不参与排序；
5. **融合**：RRF（k=60）；查询含词法锚点（配方/工艺/收率/设备/型号/数字等）时权重 0.75/0.25 偏向 BM25，否则 0.5/0.5（固定规则，非拟合调参）；
6. **切分**：约 500 字块、80 字重叠，段落/句号边界优先；标题跨页继承；维修历史按事件行隔离并提取事件期间（PDF 换行日期合并）。

*版本与来源*：知识版本指纹 = 源文件哈希 + 术语哈希 + 解析器版本 + 嵌入模型 SHA，任一变化自动重建；每条证据带 `evidence_id`、源文件名、位置（第 N 页/段落 N/表格 N/行 N–N）、来源哈希。

**效果**：检索结果逐条携带适用性判定（适用/不适用及原因，如"事件不在分析期间""文档尚未生效"）；向量路失败时显式 DEGRADED 而非静默降级；LlamaIndex `BaseRetriever` 适配层让上层以框架节点消费（满足 6.1 RAG 框架要求）；知识中心支持用户上传 PDF/DOCX/TXT 增量入库（数据中心/知识中心页面，见第 6 节）。

### 1.3 报告生成与双格式导出（赛题 5.1.3）——✅

**要求**：按分析主题（月度/季度/专题）+月份+产品自动生成完整报告；融合模板结构+数据填充+RAG 增强+大模型分析文本；PDF/Word 双格式，专业排版（页眉页脚、表格样式、图表嵌入）。

**实现与原理**（`narrative.py / reports.py / jobs.py`，流水线）：
1. 确定性引擎先出**单一指标快照**（所有数字唯一来源，API/看板/报告共享同一份）；
2. RAG 检索该产品/期间适用证据；
3. 大模型按**受限生成合同**产出归因文本（防幻觉机制见 3.3 节）；
4. 模板渲染：占位符按语义映射回填，动态表格（要素明细/趋势/原料价格/对标差异/建议/整改任务）按锚点插入；matplotlib 渲染趋势图等图表嵌入 DOCX（Noto Sans SC 字体）；表格统一样式、封面元信息、证据来源附录；
5. DOCX → LibreOffice 转 PDF（超时与转换器版本控制，容器内可用）；
6. 产物 SHA256 登记 + 存在性/哈希健康检查（损坏产物触发 Agent 决策重出报告）。

**效果**：月度/季度（季末月聚合三个月）/专题三种类型全支持；七场景验收 docx+pdf 双格式全 PASS；容器（Docker 镜像内置 LibreOffice + 中文字体）内转换 PASS；DEGRADED（如无密钥）显式标注不冒充成功。降级缓存问题已修复：`retry:true` 显式重试，旧结果保留、新任务复用确定性计算。

### 1.4 评测要求（赛题 5.1.4）——✅（机器）/⏳（人工）

- **报告结构完整度**（是否包含模板所有章节）：机器验收——标题序列必须与模板章节完全一致 + 残余占位符检查 + 数值角色绑定核对，七场景全 PASS；
- **归因合理性人工评分（0–5）**：⏳ **待真人评分**。系统已留评分入口与待评表，AI 不代填；此前任何回执均如实标注 PENDING；
- 附带：RPA 触发成功率 7/7、三步法输出格式正确率机器 PASS（见第 4、5 节），已并入评测报告交付物。

## 2. 模块二：单品成本看板与归因分析

### 2.1 看板数据层（赛题 5.2.1）——✅✅

**要求**：成本要素时间序列；环比/同比/预算偏差；贡献度 = 该要素变动额 / 总成本变动额 × 100%。

**实现**（`backend/pharma/metrics.py: analyze`，单一确定性快照）：

*计算原理*：
- 全链 **Decimal 精确算术**（无 float 累积误差），公式版本号 `cost-formulas-1.1` 跟踪口径；
- 环比/同比/预算共用同一 `change()` 函数：返回本期/基期/变动额/变动率；**缺数据不乱算**——本期无可定义数值（产量 0/数据缺失）、缺比较期、基期为 0 各有显式 N/A 原因，不补零不造数；
- 季度口径 = Σ期间成本 ÷ Σ独立产量（不是月度单位成本平均）；
- **贡献度**：要素变动额 ÷ 同口径总变动额 × 100%，单位口径与总额口径各自计算、各自分母；总变动为 0 或基期缺失 → N/A 带原因；贡献度允许为负或超 100%（数学事实不裁剪）；
- 预算差异另有**量价桥**：`(实际量−预算量)×预算单位成本 + 实际量×(实际单位成本−预算单位成本)`，显式声明"不是采购单价×实物耗量分解"；
- 每个指标登记公式文本、分子/分母、行键、源数据哈希——报告中任何数字可回溯到原始行。

**效果**：近 6 个月趋势序列（含分要素）随快照输出；原料明细（按药材的单位消耗成本环比与对材料变动的贡献度、按 |变动额| 排序）、费用明细（按类别）、工时三指标（万盒工时/折算时薪/人日效率）齐备；缺明细的工厂/期间显式"该工厂/期间无明细；不按比例推算"。跨路径口径一致性由 `metric_contract.py` 合同（制药与通用两条聚合路径同一套核心指标校验）+ 三上下文回归锁定。

### 2.2 可视化展示（赛题 5.2.2）——✅✅

**要求**：ECharts 趋势图（近 6 个月单位成本折线）、瀑布图（成本变动分解）、结构图（饼/环形）；热力图（可选加分）。

**实现**（`frontend/src/Analysis.tsx / ProductMonthHeatmap.tsx`）：
- 趋势折线（近 6 个月单位成本，可切总额口径）；
- 瀑布图：基期→各要素变动→本期的堆叠柱分解，**可切换环比/同比/预算三种比较口径**，N/A 时显式说明不硬画；
- 结构图：本月成本构成环形图；
- **热力图（加分项已实现）**：产品 × 月份 × 成本要素三维交叉（`ProductMonthHeatmap`）；
- 要素明细表与告警联动：超阈值单元格标"重点分析"。

### 2.3 归因分析自动生成（赛题 5.2.3）——✅✅

**要求**：大模型接收看板波动 JSON 自动生成"可放入正式报告"的归因段落（定位到要素/原料、引用知识库、建议可执行）；±10% 波动阈值告警自动生成重点分析。

**实现与原理**（`narrative.py: generate/validate_findings`，受限生成合同）：
- **数字与文字分工**：确定性引擎管全部数字，模型只写归因文本。模型输出的每个 Finding 必须遵守结构化合同：声明类型枚举（数值事实/文档事实/假设/证据不足/建议）、引用的指标 ID 与证据 ID 必须真实存在、引文必须逐字（≥4 ≤180 字符）存在于证据原文并带位置、适用性判定必须通过；
- **数字防幻觉**：文本中数字只能来自类型化槽位 `[[metric:id]]`（渲染期替换为注册值）或与已注册完整值一致的字面量；自由编造数字在验收期拒收；
- **失败定向重试**：按失败单元（task_id）只重掷失败部分，已通过解释冻结不重复消耗；
- **±10% 告警**：严格 `|rate| > 10`（恰好 10% 不触发，"严格超限才触发"有测试锁定）；触发的告警生成稳定 alert_id，**必须**被一条绑定该告警（alert_refs）的假设/证据不足类解释覆盖，缺失即 `ALERT_EXPLANATION_MISSING` → 整份报告 DEGRADED；主要差异章节缺实质解释同样 DEGRADED（数值复述不算归因）；
- 模型身份核验：每次调用比对响应 model 与请求 model，不一致记 MISMATCH、不得宣称目标模型实调成功。

**效果**：赛题示例级质量要求（"直接材料环比 +5.3%、贡献 68%、A 药材价格…B 药材单耗…建议①②"）由机制保证：要素定位=必填章节与指标绑定、原料级归因=materials_summary 排序注入、工艺/行业引用=证据引文逐字核对、可执行建议=五字段结构化（核查对象/证据/责任岗位/期限依据）。GLM 实调四场景模型参与维度全 PASS；DeepSeek 备选链路七次调用通过。

## 3. 模块三：对标分析三步法

### 3.1 三步法引擎（赛题 5.3.1）+ 输出（5.3.2）——✅✅

**要求**：找差异（差异金额/差异率总览表）→ 拆结构（按要素/产品逐层拆解定位来源）→ 拆原因（RAG + 大模型归因 + 改进建议）；输出差异对比表、归因文本、可转 RPA 的建议列表。

**实现与原理**（`metrics.py: benchmark/benchmark_analysis` + `narrative.py` 对标合同 + `reference_report.py`）：
- **找差异**：两厂同产品同期快照对比（Decimal），差异总览表 = 单位成本/总成本/产量 × 差异金额 × 差异率；比较方向显式声明（"左厂−右厂，以右厂为分母"），不存在方向歧义；
- **拆结构**：按成本要素逐项拆解，每要素差异额给出**占跨厂单位成本总差额的贡献度**（分母为跨厂总差额，非单厂环比）；可下钻至两厂原料/费用/工时明细（`details.left/right`），明细不可用时明确列出缺什么；
- **拆原因**：`benchmark_analysis` 把跨厂指标打包为独立命名空间 `benchmark:*` 的注册指标；模型在对标章节**只能引用跨厂指标**（借用单厂环比指标直接验收拒绝——防归因偷换口径）；RAG 检索行业/工艺知识（范围预过滤照常生效）；输出=假设类归因 + 缺证清单 + 结构化改进建议（建议五字段与整改任务同构，可一键转任务草稿）；
- **口径一致**：对标表数值/单位/标题/差异公式共用同一口径来源（`benchmark_unit_of`）——选总额口径时表头与数值自动标"元"，单位口径标"元/盒"；篡改单位会被验收器抓住（负例测试锁定）；
- 无跨厂可比数值时只允许"证据不足"类结论，不得编造差异原因。

### 3.2 对标评测要求（赛题 5.3.3）——✅

- **输出格式正确率**：必要字段（产品×要素×差异金额×差异率×贡献度×方向声明）由报告验收器核对，七场景 PASS；
- **差异计算准确率（误差 ≤1%）**：Decimal 精确算术 + golden 独立手算对照（`test_industry.py` 黄金值），实测误差 **0**；
- 归因逻辑自洽：假设必须绑定跨厂指标引用与证据/缺证清单，未绑定验收 FAIL。

## 4. 模块四：RPA 整改任务闭环

### 4.1 整改任务生成（赛题 5.4.1）——✅✅

**要求**：大模型按分析结论生成结构化整改任务 JSON：任务标题、责任人（部门/岗位）、任务来源（关联场景与归因）、优先级、截止时间。

**实现**（`actions.py: ExecutableAction` 合同 + `narrative.py: ProposedAction`）：
- 赛题五字段全覆盖（标题/责任人部门岗位/来源关联分析场景与归因结论/高中低优先级/截止时间），**另加**核查对象、预期证据、责任角色、期限依据——把"建议"升级为"可执行核查任务"；
- 合同校验：任何字段空值或残留 `{{}}`/`[[]]` 占位符即拒收（`UNRESOLVED_OR_EMPTY_ACTION_FIELD`）；截止日期由期限依据解析提案、确认前可调整。

### 4.2 RPA 调度与消息推送（赛题 5.4.2）——✅✅

**要求**：HTTP API 发送任务 JSON 至模拟 RPA；返回 200=成功触发；模拟微信发送闭环 + 前端"已发送至 XX 责任人"。

**实现与原理**（`actions.py: ActionStore/outbox` + `synthetic_rpa.py` + `local_validation.py`）：
- **确认后发送**：草稿 → 人工确认（绑定 payload_hash，确认的就是发送的）→ 事务 outbox → HTTP POST 题 包 mock RPA；未确认内容不可发送（超出赛题的安全边界）；
- **协议校验**：响应必须符合 mock 协议（code 整数 + status 枚举 + task_id），微信送达按题包中文回执模式（"已发送至 XX(部门)"）+ 状态历史双重判定；回执不符不算送达；
- **回环边界**：默认仅允许 loopback 目标（Docker 内部模拟器需显式 opt-in 环境变量），防 SSRF；
- 前端任务卡显示接口请求/模拟通知/整改进度三个独立维度，"模拟送达≠整改完成"贯穿 UI 文案。

**效果**：RPA 触发成功率 7/7（评测回执）；发送失败/结果未知有状态与重试路径。

### 4.3 任务追踪看板（赛题 5.4.3 加分项）——✅

已生成任务数（按任务 ID 去重）/模拟通知送达数/责任人确认数三卡统计；责任人确认须本人署名+时间+备注，确认只代表"收到将跟进"，不登记整改完成。决策台账（见 5.2）与任务看板共同构成审计链。

### 5.2 加分技术（6.2）——✅✅ 四项全有实测证据

1. **知识图谱增强 RAG**（`graph.py`）：从配方/工艺文档**确定性正则抽取**（处方行=序号+药材+剂量、工艺=箭头链），节点/边带剂量与页码溯源，解析不到不编造；增强方式受控——图谱邻居（该产品的药材名/工序名）只注入 BM25 查询词，不改变向量路与适用性合同；知识版本变化图谱自动重建。实测规模：3 产品/11 药材/7 工序/27 边，前端力导向图可视化；增益标注为实验性（诚实披露）。
2. **多模型协作**（`narrative.py: for_route / PHARMA_MODEL_ROUTES`）：路由表 route→{model, base_url, protocol, key_file}，叙事与决策分路由（报表大模型、决策说明小模型）；三处调用统一经 `for_route()` 解析（页面配置=实际调用，有请求账本佐证）；每次调用身份核验（响应 model==请求 model），主端点余额耗尽自动回退备选端点（`calls.endpoint` 可审计）。
3. **Agent 自主决策**（`decision.py`）：判断"生成报告 vs 仅更新看板"。**决策本体是版本化确定性策略**（无报告→重出；快照绑定过期→重出；产物缺失/哈希不符→重出；否则仅看板），模型**不能翻转决策**，只从已验证信号中选择依据并转写说明（输出形状与信号合法性校验，越界即 DEGRADED）；每次决策写 SQLite 台账（信号/依据/模型说明/后续任务号）可回放。
4. **成本预测**（`forecasting.py`）：Holt 双参数指数平滑（α=0.6/β=0.3 固定不调参），只消费已固化趋势数据；区间=样本内一步残差均方根（显式标注"实验性、未验证覆盖率"）；不足 3 个连续月或断月 → `INSUFFICIENT_HISTORY` 拒绝输出而非伪造；附朴素基线（末值）与样本内 MAE 对比 + 管理告示文案。
