### A. API 与任务系统（11 条：确认 7、未证实 4）

**A1｜`05_原型/backend/pharma/api.py:419-422`｜高危｜已确认**
GET `/api/reports/{job_id}/acceptance` 对 QUEUED/RUNNING 任务无终态校验，`_recalc_acceptance`（api.py:373-375）无条件 `UPDATE jobs SET status=...`（WHERE 仅 id），把运行中任务改写为终态；`jobs.py:106` 的 `next()` 只取非终态任务，worker 从此不再处理——一次普通 GET 即可冻结执行中的报告任务（产物缺失）。证据：api.py:421 直接调用无状态检查，对比 api.py:350 提交评审入口有 `REVIEW_TARGET_NOT_FINAL` 守卫；`assess_report` 全程 `.get()` 容错，对中间态返回 FAIL→DEGRADED，UPDATE 必然执行。
复核：高危恰当。影响面修正：RUNNING 中任务可能被 worker 后续更新覆盖回真终态（冻结多为暂时），主要破坏的是 worker 崩溃重启后对停摆 RUNNING 任务的重新拾取；前端无自动 GET 该端点（仅 POST acceptance-doc），默认部署无 API token（api.py:35-43），任何本地请求可触发；同 cache_key 重新提交可走 repair 分支间接重建，但原任务数据已损坏且以假完成态示人。

**A2｜`worker.py:140-150`｜中危｜已确认**

写 `record.json` 的 `write_text` 未指定 encoding，未启用 UTF-8 模式的中文 Windows（cp936）下，result 含 emoji 等 GBK 外字符抛 `UnicodeEncodeError`，docx/pdf 已生成成功的任务在最后一步被标 FAILED，产物因终态 FAILED 不可下载（jobs.py:132-133 `ARTIFACT_JOB_FAILED`），重试复用同 narrative 会反复失败。
