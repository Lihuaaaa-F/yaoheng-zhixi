## 第一部分：一份数据从导入到产出的全部流程

系统有两条等价的入口路径，汇入同一条分析-报告管线：

```
路径A（用户自助）                          路径B（赛题数据包）
数据中心·上传 → 导入列表等待                competition_configuration +
   │「解析数据」一键流水线                  00_赛题原始资料（只读）
   ▼                                          │ bootstrap 摄取
import_pipeline.run_data_parse                ▼
   └→ 注册企业上下文 imp-xxx          ingestion.ingest（勾稽→parquet）
        └───────────┬──────────────────┘
                    ▼
        分析快照 metrics.analyze（±10%告警自动入队）
                    ▼
        RAG 检索 context_services.retrieve（BM25+向量+图谱扩展）
                    ▼
        叙事生成 narrative.generate（大模型+解释合同）
                    ▼
        报告渲染 render_docx（模板书签绑定）→ convert_pdf → verify/验收
                    ▼
        整改闭环 actions（草稿→确认→模拟RPA送达→责任人确认）
```

### A1 上传（数据中心三子项共用）

| 项 | 内容 |
|---|---|
| 入口 | `POST /api/imports/uploads`（kind=business/knowledge/template + data_type + 文件） |
| 处理 | 字节原文保存 `.runtime/imports/{sha256前16}-{kind}/original.*`（永不转码）；编码探测 utf-8-sig/gb18030/big5；表预览（表头+8行样例+建议映射+表头指纹） |
| 存储 | `imports.sqlite3`：id/kind/status=UPLOADED/filename/encoding/size/sha256/meta |
| 校验 | 50MB 上限；扩展名-kind 白名单（csv/xlsx→business，pdf/docx/txt→knowledge，docx→template）；同内容重复上传幂等 |
| UI | 导入列表显示 数据类型/文件名/格式/大小/状态/预览按钮；预览弹窗实时读原始文件（表格前200行/PDF内嵌/DOCX文本抽取） |

### A2 解析流水线（点击「解析数据/构建知识索引/解析报告模板」）

任务入队（`data_parse`/`kb`/`template_parse` kind），worker 串行执行，`jobs` 表逐段写入 progress(0-100)+detail，前端进度条轮询 `/api/jobs/{id}`。终态消息合同：「数据处理成功 / 数据处理失败，{出错步骤}报错」等。

**业务数据六步**（`import_pipeline.run_data_parse`）：
1. **PREPROCESS 预处理**：编码/工作表/表头读取；空表头即失败。
2. **MAPPING 智能字段映射**：按数据类型组合——明细类（原材料/制造费用/人工/预算）用**确定性固定映射**（含题包实际表头"元/盒"变体）；汇总类走**预设映射**（表头指纹命中成本宽表）；两者不足时调用**数据提取模型（小模型，当前 deepseek-flash）建议映射**，带数值性防护（文本列不得映射为金额——模型幻觉映射拒绝）；无模型时确定性回退不阻塞。
3. **VALIDATE 质量校验**（`data_import.validate_business`）：维度必填（工厂/产品/期间）、数字有效性、**同键冲突产量**、重复金额提示、产量为0、期间规范化（2026年3月/2026-03 等）；错误**定位到文件/工作表/行号**中文原因；能力预览（缺产量→仅总成本分析、缺基期→无同比等，缺什么说什么不可用）。
4. **ATTRIBUTION 归因分析**：发布后对新数据集跑告警提取（±10% 严格阈值）+ **数据分析模型（大模型）归因推测**（定性假设+缺失证据清单，数字只能引用输入）；无模型时确定性规则假设。
5. **PUBLISH 合并发布**（`publish_business_batch`）：多文件按类型优先级合并——**成本汇总 > 预算 > 明细**（同键金额以高优先级为准，防止汇总+明细双计；产量任何冲突即失败）；Decimal 运算；生成 facts.json（产量独立成事实+要素成本事实，含 source_row 溯源）+ enterprise.json；`industry.register_enterprise` 全部校验先行、注册表原子替换（失败不破坏现有数据）。
6. 新上下文 `pharmaceutical:imp-xxx` 立即出现在数据范围目录，全程约 1-3 分钟。

**知识库数据**（`run_kb_build`）：解析待入库文档（PDF按页/DOCX段落/CSV转文本）→ 落知识入库目录（文件哈希进入知识版本指纹）→ `Knowledge.build`：文档分块（标题继承/维修事件行隔离/产品范围判定，~500字符+80重叠）→ **BM25 词法索引**（jieba+FTS5，术语表分词增强）→ **向量索引**（本地 bge-large ONNX 逐批编码入 Chroma，进度按批上报；向量失败降级词法不冒充成功）→ 清单校验并切换 CURRENT。消息「知识库构建成功（向量降级说明）/ 构建知识库失败，{步骤}报错」。

**报告模板**（`run_template_parse`）：章节契约检查（六固定章节，兼容 Heading1 与中文编号样式、前缀匹配）→ 占位符提取（段落+表格单元格，≥20）→ 语义绑定分析（大模型辅助+确定性 binding_semantics 兜底）→ 安装为对应类型当前模板（`RUNTIME/templates/{type}.docx`，改名合同+前置区手术+同比补绑定；未安装类型回退题包工作模板）。

### B 赛题包摄取路径（`ingestion.ingest`）

10 个 CSV 全量读取（文件名映射 7 类 kind）→ **audit 勾稽审计**：数值有限性/非负、主键唯一、期间连续、**算术关系**（单位成本=Σ三要素、总成本=产量×单位成本、明细 rollup 对账、工厂/产品/规格须在主数据合同内）→ duckdb 生成 parquet + `current.json` manifest（快照指纹）。字段数错配行报清晰校验错而非崩溃（2026-09-22 加固）。

### C 分析快照（`metrics.analyze` / `industry.analyze_reference`）

行过滤（工厂×产品×期间）→ 期间聚合（缺月不补零）→ 三要素单位/总额 → 环比/同比/预算三基期对比 → **贡献度=要素变动额/总成本变动额×100%** → 预算桥（量差/单位成本差）→ 人工工时派生指标（工时/万盒、时薪、效率）→ 原料贡献排序（材料增量占比）→ 行业基准分位（类别匹配+规格换算 divisor）→ **±10% 严格告警**（单位与总额分别判定）→ 快照整体 sha256 作 snapshot_id 存 SQLite。`/api/analyses` 返回时若存在告警，按版本指纹幂等自动入队报告（PHARMA_AUTO_EXPLAIN 默认开）。

### D 检索增强（`context_services.retrieve`）

知识源幂等校验（build）→ **混合检索**：BM25（FTS5，术语分词）+ 向量（Chroma cosine）双路召回 → RRF 融合（词法锚词查询 0.75/0.25，否则 0.5/0.5）→ 适用性过滤（产品/工厂/期间/规格/文档版本/上下文六维，不适用给原因）→ 知识图谱邻居词扩展（所选产品的药材/工序补进 BM25 查询）→ 目的检索（事件槽位补查）。

### E 叙事生成（`narrative.generate`，glm-5.3）

程序按告警/章节生成 `explanation_tasks` → 大模型在**解释合同**下输出：只允许 hypothesis（证据支持假设）/insufficient_evidence（证据不足）两类定性结论；**任何自由数字整体拒绝**（唯一例外：注册指标四舍五入简写）；证据引用必须逐字引文且过适用性校验；每条假设强制 missing_evidence 清单；告警覆盖检查（漏解释即 DEGRADED）；修复循环≤2轮；数字经 `[[metric:id]]` 槽位由程序渲染（合同 v10：ROUND_HALF_UP 唯一来源、方向词担符号）；无模型时规则化回退。

### F 报告渲染与验收（worker 七阶段）

VALIDATING（输入版本指纹核对，模板/知识/模型/提示词任一变化要求重新提交）→ COMPUTING → RETRIEVING → GENERATING（对标 benchmark_analysis）→ RENDERING_DOCX（按报告类型选模板：安装模板优先/回退题包工作模板；70+ 处数值书签绑定核对；动态表 5 张；图表 4-5 幅；**归因方向评估**确定性生成：材料×行情同向→价格传导可能性较高→单耗→产量分摊，每条附证实/证伪记录清单）→ CONVERTING_PDF（LibreOffice+目录回填≤5轮）→ VERIFYING（`assess_report`：文件可开/计算一致/证据适用/任务可执行/模型实际参与 自动；章节实质/可读性/版式 留真人）。产物哈希入 artifacts 表，下载带完整性校验。

### G 整改闭环（`actions.py` + worker outbox）

大模型 findings 中可执行建议（无占位符残留+五要素齐全）→ 草稿（任务 JSON：task_title/责任人部门岗位/来源（场景+归因+期间）/优先级/截止默认7日/payload_hash）→ 确认（哈希防篡改）→ worker 投递官方 mock RPA（HTTP 200=SIMULATED_SENT）→ 状态查询 → 责任人署名确认（模拟送达≠整改完成的边界全程明示）。

### H 贯穿的版本与指纹体系

context_hash（数据+政策+知识+模板）→ snapshot_id → knowledge_version（源文件+术语+向量模型指纹）→ template_version → 模型/提示词版本 → 报告缓存键=全部指纹的 sha256。**任何输入变化自动使旧结论失效并要求重算**，这是全链路可复现的根基。

## 第二部分：现行归因方法剖析

现行体系是**四层"程序定量、模型定性"架构**：

| 层 | 方法 | 数学/逻辑 | 位置 |
|---|---|---|---|
| L0 确定性核算 | 贡献度分解；预算桥；原料贡献排序；行业分位 | 贡献度ᵢ=ΔCostᵢ/ΔCost_total×100%（会计恒等式，Σ=100%精确可加）；桥：(Q₁−Q₀)×UC₀ + Q₁×(UC₁−UC₀) | metrics.py |
| L1 方向评估 | 三通道可能性排序 | ①材料成本方向×药材行情方向**同向**→"价格传导可能性较高"，反向→指向单耗；②单位耗用（工时/效率派生）；③产量分摊（固定费用摊薄）；每条附"证实或证伪"记录清单 | reports.build_bindings |
| L2 模型假设 | LLM 受合同约束的假设生成 | hypothesis/insufficient 二分；证据双要素（逐字引文+缺失清单）；数字槽位化；告警全覆盖检查 | narrative.py |
| L3 检索/图谱 | 证据召回与假设支撑 | RRF 混合检索+适用性过滤；KG 邻居词扩展 | knowledge/context_services |

**强项**（这是设计选择而非缺陷）：数字全部程序拥有（可复现、可审计、Decimal 精确）；"证据支持假设 vs 证据不足"二分诚实合同与领域语言一致；证据可溯源到文档页码；方向评估已含"行情同向"这一朴素因果线索。

**五个缺口**（对照业界方法得出）：
1. **无严格量价分解**——预算桥明示"不是采购单价×实物耗量分解"；原材料明细只有金额，缺单价×耗量两列，材料价差/量差不可分。这受数据边界约束（题包无采购价），但导入通道已具备扩展能力。
2. **序贯分解的口径依赖**——瀑布/贡献度按要素序贯表述，多因素**交互项**未公平分配（哪个要素"先动"影响表述口径；会计惯例可接受，学术上是 Brinson 类方法的已知缺陷）。
3. **假设无量化排序**——方向评估只有定性"可能性较高"；没有可比较的解释力分数。
4. **无反事实估计**——"若胶囊机未故障，单位成本会是多少"无法回答；对标章节有对照厂数据但未形式化为因果估计。
5. **多维定位缺位**——告警是单指标×单产品×单厂触发；"哪个 维度组合（产品×工厂×要素×药材）解释了本期总成本异常"没有系统搜索。

## 第三部分：业界优秀方法拆解归类

按**思维框架**归为六族（各含：框架/逻辑链/数学/理论依据/对本项目适配度）：

### 族1 会计差异分解族（标准成本差异 / PVM / Brinson）

- **框架**：先验业务恒等式代入分解——不问数据、问公式。管理会计百年传统。
- **逻辑链**：总差异 ≡ Σ 分量（精确可加，无残差）；每个分量对应一个可行动的责任口径（采购部管价差、生产部管量差）。
- **数学**：材料价差=(实际价−标准价)×实际量；材料量差=(实际量−标准量)×标准价；配比差异（实际配比与标准配比加权重定价）；PVM：量差=ΔQ×P₀、价差=ΔP×Q₀、结构差异=组合权重变化的重定价残差；Brinson：按权重×收益率双维分解。
- **理论依据**：标准成本制度（管理会计教科书体系）；可加性来自恒等式代数。
- **适配度：★★★★★（有数据即用）**。与本项目 Decimal/可加/可测试合同完全同构；解锁条件只是数据模板加两列（采购单价、实物耗量）。PVM 的"mix"对本项目=药材配比变化，恰是制药工艺的核心变量。

### 族2 博弈论公平分配族（Shapley 值）

- **框架**：把各成本动因视为"玩家"，总变动是"联盟收益"，求每个玩家的**平均边际贡献**。
- **逻辑链**：序贯分解（Brinson/瀑布）的结果依赖分解顺序；Shapley 对所有 2ⁿ⁻¹ 种加入顺序取平均，唯一满足效率/对称/哑元/可加四公理的公平分配。
- **数学**：φᵢ=Σ_{S⊆N\{i}} [|S|!(n−|S|−1)!/n!]·[v(S∪{i})−v(S)]；对 n≤6（三要素+产量+配比）可**精确枚举**，无需近似。
- **理论依据**：合作博弈论（Shapley 1953）；金融风险归因中已作为 Brinson 的顺序无关替代。
- **适配度：★★★★（补交互项的即战力）**。项目原料数 3-8、要素 3-5，n 小到可精确计算且完全确定性（符合同输入同输出合同）；能回答"材料涨价与单耗上升**共同**造成多少"这类交互问题。

### 族3 多维异常根因族（ADtributor / HotSpot / Squeeze / iDice / RiskLoc / CMMD）

- **框架**：指标存于多维立方体（产品×工厂×要素×月份×药材…），异常发生时在立方体上**搜索最能解释异常的属性子集**。
- **逻辑链**（ADtributor）：计算各维度各属性的**解释力 EP**（该属性解释的异常占比）与**惊奇度 surprise**（Jensen-Shannon 散度度量实际与预测分布差异）→ 逐维度贪心选择 EP≥阈值且 surprise 最大的属性集合。（HotSpot）：定义**潜在增益**（叶子集合解释异常的能力），在 ps-tree（属性组合的层级搜索树）上剪枝搜索，蒙特卡洛显著性检验；处理衍生指标（比率型 KPI）。（Squeeze）：进一步泛化到衍生度量并提高鲁棒性。（CMMD/RiskLoc）：放宽"根因仅在单一维度"假设，处理跨指标。
- **数学**：JSD(p‖q)=½KL(p‖m)+½KL(q‖m)；EP(c)=Δ_c/Δ_total（可加指标）；潜在增益=组合的异常贡献与其 BDE 概率的函数；组合搜索+树剪枝。
- **理论依据**：信息论（散度=信息增益）+ 组合优化；工业界（微软/清华 NetMan）在广告收益与搜索引擎 KPI 上验证 95%+ 定位准确率。
- **适配度：★★★★★（本项目的镜像场景）**。广告收益调试与"成本异动归因"结构同构：可加指标（收入↔总成本）、多维属性（广告位/地域↔产品/工厂/要素/药材）。**需确定性化改造**：HotSpot 的蒙特卡洛/Pearson 换成 JSD+确定性集合搜索（同输入同输出，符合项目合同）；数据立方体项目已天然具备（ingestion 行即立方体事实）。

### 族4 因果推断族（潜在结果 / SCM / DiD / 合成控制 / DoWhy 四步）

- **框架**：反事实视角——"若原因不存在，结果会怎样"；相关性≠因果性需要设计。
- **逻辑链**（DoWhy 统一四步）：**模型**（因果图编码先验知识）→**识别**（do-演算把因果量化为可估统计量）→**估计**（效应量）→**反驳**（安慰剂/随机子集等稳健性检验）。DiD：处理组前后变化−对照组前后变化=处理效应（平行趋势假设）；合成控制：无单一对照时用多对照单位加权拟合处理组的前期轨迹。
- **数学**：E[Y|do(X)]=Σ_z E[Y|X,z]·P(z)（后门调整）；DiD 估计量 τ̂=(Ȳ_treat,post−Ȳ_treat,pre)−(Ȳ_ctrl,post−Ȳ_ctrl,pre)；合成控制权重最小化前期轨迹距离。
- **理论依据**：Neyman-Rubin 潜在结果框架；Pearl 结构因果模型/do-演算；Abadie 合成控制。
- **适配度：★★★（用其"形"，慎用其"量"）**。完整 SCM/因果发现在 n=6 月×3 品的数据量下不可辨识；但三个组件高度可用：①**因果图作为假设先验**——本项目知识图谱（药材→材料成本、工序→收率→单耗、设备→停机→产量→摊薄）正是现成的因果候选 DAG；②**DiD/对照厂**——跨厂对标数据天然提供对照组，可对"事件月"（设备故障/工艺变更）给出效应估计，输出保持"估计值+假设声明"；③**反驳步骤**——安慰剂检验（对无事件月份跑同法应得零效应）可作为程序的自动稳健性检查。

### 族5 时序先行族（Granger 因果等）

- 框架：X 的历史是否改善对 Y 的预测。数学：滞后回归 F 检验。理论：Wiener-Granger 因果。
- **适配度：★（不适用）**。Granger 需要≥数十期观测，本项目月度数据仅 6-12 期，检验功效不足且易假阳性；明确排除并记录理由。

### 族6 LLM 因果推理族（学界分工共识）

- 学界 2024-2025 共识：LLM 作为**推理引擎**（直接断因果——在受控基准上不可靠，幻觉风险）与作为**助手**（先验知识注入、假设枚举、证据摘要、解释生成——可靠且增值）两类用法（arXiv 2024 综述；IJCAI 因果发现综述：直接评估/先验增强/后验精化三模式）。
- **适配度：★★★★（现行架构恰是正确用法）**。本项目的"数字程序所有+模型只做定性假设"合同与学界最佳实践一致；提升空间在**给模型喂结构化的定量中间件**（族1-3 的输出），让它解释的是"已量化的分解"而非"原始波动"。

## 第四部分：适用于本项目的归因方法体系（综合方案）

设计原则：**兼容现行四层架构与其诚实合同**（Decimal 确定性、数字程序所有、证据支持假设/证据不足二分、缺数据不臆造），在其上增加三层"定量归因中间件"，构成 **"分解→定位→反事实→排序→解释"五层体系**：

### 新L0′ 严格差异分解层（族1+2）
- **数据**：原材料明细模板增两列——`采购单价(元/kg)`、`实物耗用量(kg)`（数据中心"成本明细数据"新数据类型 `purchase_detail`，或既有明细加列；无此列时能力预览如实声明"价量不可分"）。
- **方法**：材料价差=(AP−SP)×AQ；材料量差=(AQ−SQ)×SP；SQ=标准单耗×实际产量（标准单耗来自配方文档 KG 剂量——图谱已有！）；**配比差异**（药材组合权重变化重定价）；多因素交互用 **Shapley 精确分配**（n≤8 可枚举，确定性）。
- **输出**：瀑布图从"三要素"细化为"价/量/配比/交互"，每格带责任口径（采购/生产/工艺）。

### 新L1′ 多维根因定位层（族3 确定性化）
- **数据**：ingestion 行即立方体（产品×工厂×要素×药材×月份），已有。
- **方法**：ADtributor 式——异常月对每个维度属性计算 **解释力 EP=Δ_c/Δ_total** 与 **surprise=JSD(实际分布,基期分布)**；确定性贪心+集合搜索（替换蒙特卡洛），输出 Top-K 根因集（如"`{产品:银黄, 要素:材料, 药材:金银花}` 解释 6 月材料成本异常的 78%，surprise 0.42"）。
- **输出**：告警页新增"根因定位"卡：根因集+解释力百分比+JSD；报告 4.2 成本异常点排查章节直接引用。

### 新L2′ 反事实估计层（族4 的 DiD/对照厂）
- **数据**：跨厂对标数据（已有）+ 事件标注（维修记录/工艺变更——知识库已有此类文档，图谱事件行已提取）。
- **方法**：对事件月，τ̂=(Y_厂,post−Y_厂,pre)−(Y_对照厂,post−Y_对照厂,pre)；安慰剂检验自动跑（无事件月份应≈0，超界则标注"平行趋势存疑"）。
- **输出**："若未发生胶囊填充机故障，估计 2 月单位成本低 δ 元/盒（DiD 估计，依赖平行趋势假设，建议人工复核）"——估计值+假设声明，符合诚实合同。

### L3′ 假设排序层（升级现行 L1 方向评估）
- **方法**：因果候选集来自**知识图谱 DAG**（药材价格→材料成本；设备故障→停机→产量→摊薄；工艺变更→收率→单耗）∩ L0′/L1′ 的量化线索；程序打分：score = 方向一致性×时间窗重合×证据覆盖度（检索命中数与适用性）×解释力；输出**带分数的排序表**（高≥0.7/中0.4-0.7/低<0.4），每条保留证实/证伪清单。
- LLM 在此之上做定性叙述（现行合同不变）。

### 落地路线图

| 阶段 | 内容 | 依赖 | 预估工作量 |
|---|---|---|---|
| P0 | purchase_detail 数据类型+价差/量差/配比分解+Shapley 交互 | 用户提供采购单价/耗量列（模板已设计） | 2-3 天 |
| P0 | 多维根因定位（EP+JSD 确定性版） | 无新依赖（数据已有） | 1-2 天 |
| P1 | DiD 对照厂反事实+安慰剂检验 | 事件月标注（知识库已有部分） | 1-2 天 |
| P1 | KG 因果候选+证据评分排序 | 图谱已有 | 1-2 天 |
| P2 | 报告/看板 UI 呈现细化（根因卡/反事实框/排序表） | P0-P1 | 1-2 天 |

**合同兼容性论证**：全部新层输出均为程序计算的 Decimal 数值（可测试、同输入同输出）；Shapley 精确枚举无随机性；JSD 确定性；DiD 估计显式携带假设声明；LLM 职责不变——业界调研（族6）恰好证明该分工是学界共识，数字约束不是保守而是正确。
